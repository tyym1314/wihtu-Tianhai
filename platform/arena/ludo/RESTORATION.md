## Visual restoration — 2026-09-19

The interactive board keeps its 52-cell topology and two pawns; the original concept is the visual reference rather than an authority for cell count. This pass adds painted preset portraits, enlarged player halos, separate colored lacquer shading, layered gold framing, a six-sided CSS 3D die, and event-driven capture sparks with curved flights back to the actual victim bases. Die rolls use the shared `dice` audio hook; captures still use authoritative shared event playback. No client dice generation, score changes, or rules changes were introduced.

New implementation: `visual-kit.jsx`, `restoration.css`, with edits to `LudoGame.jsx`. The portrait atlas is reused by the other two restored games. Source, prompt and delivery conversion are recorded in `assets/provenance.json`; `players-source.png` is retained, and only the 768-square WebP is imported by the UI. These are cosmetic preset characters, not authenticated player photos.

Screenshots: `review/restored-390.png`, `restored-360.png`, `restored-capture.png`. Run `node arena/ludo/review-restoration.mjs` and `node arena/ludo/review-restoration-events.mjs` from platform for all three isolated restoration checks. Reports are `review/restoration-report.json` and `restoration-events.json`. Rendering uses random HTTP ports, in-memory engine state and asset-inlining only in the review bundle; there are no wallet or shared server calls. Verified 390×844 and 360×800, no page overflow, actual roll/base exit and a legal two-pawn capture from a prepared midgame fixture. Existing engine tests across these three games: 57/57. Desktop Chrome emulates dimensions; no physical device acceptance is claimed.

Remaining art gaps: the shared vector pawn is still a lightweight approximation of the concept's sculpted pawn; exact enamel microtextures and a fully authored mascot victory sequence need dedicated material/sprite production. The themed settlement/result scene belongs to the parent shell and is not replaced here. This pass improves active play and event timing; it does not claim pixel-identical final art or sustained low-end WebView frame-rate acceptance.
