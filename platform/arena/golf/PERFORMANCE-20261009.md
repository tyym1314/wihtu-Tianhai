# Golf staged art and frame work

The scene retains the authored course layout, materials, shadows, water shading, nine content holes and versioned collision/scoring data. Desktop keeps original models; mobile uses verified decorative-only LOD geometry. No rule, server action, wallet or content change is included.

## Changes

- `preloadGolfAssets` warms common botanicals and five shared textures. The lobby has no pinned round yet; `GolfGame` reads the actual `roundGolfHole` artwork index and waits for that course GLB and AO. First authored render starts a cancellable 300 ms timer to prefetch the next pinned course. A later course switch waits for complete authored resources; its input stays disabled and the previous scene stops GPU rendering while that dependency is pending. Failed background prefetch is retryable when that course becomes current.
- Common and three course sources have separate bounded, shared generations per desktop/mobile tier. Renderer and loader use the same quality predicate; scene-owned ensureCourse retains its original tier. The two tiers cannot reuse each other's model generation. Cancelling one consumer leaves other consumers intact; cancelling the last pending consumer retires the request and decoder workers. A late failed generation cannot remove its replacement. Renderer-owned geometry/material/texture clones dispose independently of retained source objects; future-course work is aborted on unmount.
- Mobile water waves and caustics still advance every display frame. The wide, stationary scene reuses its mirror capture between at most 20 captures/sec. A changed camera, active shot or cup closeup captures every frame. Reflection texture resolution and shader remain unchanged. Mobile shadows retain the same 1024² PCFSoft map and casters; waiting views refresh it at most 15 times/sec, while active shots and cup closeups update every frame. Desktop behavior remains full-rate.
- Aim prediction receives the latest exact angle/power once per displayed frame. One dashed line and end ring persist across updates; trajectory samples and distances update existing dynamic buffers without truncation. Only changed buffer ranges upload. The authoritative submitted shot values and simulation remain unchanged.

Four fingerprinted mobile GLBs reduce only rounded stones on nonplayable garden/flower islands and palm trunk detail. Playable coastline, legal curbs, bridge, crown, flowers and fern source meshes retain vertex/face/UV/material digests before re-export. Original source `.blend` SHA values remain unchanged. Three courses fall from 97,276 / 100,624 / 96,520 triangles to 72,814 / 76,162 / 72,058 (each retains nine material primitives). Palm trunk falls from 2,664 to 1,598; leaf/flower silhouettes are preserved. A dense bidirectional vertex/edge-midpoint/triangle-center BVH comparison found maximum sampled decorative error 0.012610845 units and trunk error 0.004655118 units. This is a sampled surface metric, not a global Hausdorff proof. Existing 14-bit Draco serialization still introduces its usual quantization; decoded vertex bytes are not claimed identical.

The initial authored file barrier falls from 2,546,802 bytes (four original GLBs/eight images) to 1,283,744–1,314,014 mobile bytes (two GLBs/six images depending on selected course), about 48.4–49.6% less. The full mobile authored set totals 2,305,542 bytes. These are file bytes, not measured compressed network bytes or LOAD-01 time. Decoder, JavaScript and post-first-render prefetch are excluded. A room's existing authority timers still start under existing rules; loading wait must remain included in end-to-end entrance/shot-clock measurements. Fingerprints, source geometry digest summary and provenance live in `assets/manifest.json` and `assets/review/mobile-lod-v1/build-report.json`; `assets/source/build_mobile_lod.py` recreates candidates without overwriting original sources.
