# Dune Dash 阶段 A 技术灰盒

**本目录是技术预研，不是正式游戏、美术交付或移动端性能验收。** 四个程序化占位角色、一条简化赛道、跳跃和碰撞减速，用于验证 3D 展示与服务端状态边界；没有真钱包、金币、概率奖励、App 登录或生产身份系统。

预览：[http://127.0.0.1:8796/](http://127.0.0.1:8796/)。仅监听本机 IPv4 回环；不发布公网，不改动 8795 平台界面及 8787/8790 两款旧游戏。

## 运行

从本目录执行：

```sh
npm install
npm start
```

Three.js 与 Playwright 直接引用父 `platform/node_modules`，本目录只额外安装 `ws`。父平台依赖需已安装。HTTP 资源与 WebSocket 都由同一个 8796 服务提供。

## 怎么看

1. 打开预览，等待 4 个角色显示已连接。
2. 点击“开始 4 人测试”；你控制橙色 runner-0，空格或“跳跃”跳过障碍。
3. 另外三名在列表中明确显示“脚本测试”。每个脚本建立独立真实 WebSocket，发送与用户相同的 jump 输入；没有后台直接移动或指定脚本胜者。
4. 拖动延迟滑块，观察 RTT 和动作响应。滑块在该浏览器客户端收、发队列分别增加所选值的一半；真实网络仍是本机回环，不能据此声称跨区域弱网表现。
5. 点击“断线 1.2 秒后恢复同一角色”，可以看到服务端比赛继续、同角色带着既有位置和序号恢复。
6. 所有人冲线后显示服务端赢家、最终快照摘要。点击“重置本局”保留四个身份和连接，开启新的 matchId。

本预研只有一个内存房间，支持一组 4 人。普通预览占用 1 用户＋3 脚本座位，另开独立用户可能显示 ROOM_FULL；同一个已连接 clientId 不能被第二个页面接管。刷新相同页面使用本地恢复 token。测试脚本会清空当前灰盒房间，因此不要在演示进行中运行自动验收。

## 权威边界

- Node 服务端以固定 60 Hz 逻辑推进跑动、重力、跳跃、障碍碰撞、减速和冲线；20 Hz 向每个连接发送快照。
- 客户端只提交 `{type, action: 'jump', seq, matchId}`；拒绝位置/胜者字段、未知动作、重复序号、过大序号跨度和旧比赛输入。
- 渲染端用快照平滑展示位置，程序化摆动四肢；不把动画结束作为判胜依据。当前没有完整客户端预测/回滚物理。
- 断线不停止比赛，角色继续向前；恢复 token 绑定原角色，重新连接不重建角色、回到起点或清空序号。
- 所有客户端对同一最终结果 hash 回执，`/api/evidence` 可查看本次本地测试事件；摘要用于一致性观测，不是生产防作弊证明。
- 为灰盒简单确定性，若同 tick 冲线按 lane 顺序选首名；**正式游戏的并列分奖规则不采用这个灰盒占位规则**。
- 进程长暂停最多累计 250 ms 补步，属于防卡死保护，尚未设计生产过载/崩溃续局策略。

## 验证

```sh
npm test
npm run test:browser
```

浏览器验证由父 Playwright 驱动系统 Chrome 的 4 个隔离上下文，建立 4 个真实 WebSocket。默认使用 `channel=chrome`；可通过 `GRAYBOX_BROWSER_CHANNEL` 指定已安装的兼容浏览器渠道。不会复用用户浏览器配置。机器需已安装相应浏览器。

- `test/engine.test.mjs`：6 项规则边界、非法输入、重复序号、重连、碰撞、确定性结果测试。
- `test/browser.mjs`：真实四连接、100/150/200/250 ms 受控附加延迟、非法输入、重复序号、断线恢复、四端一致冲线结果及四份结果回执。
- `evidence/browser-validation.json`：实际浏览器与服务端证据。
- `evidence/unit-tests.tap`：单元测试输出。
- `evidence/default-preview-validation.json`：普通预览 1＋3 连接、开始、跳跃、重置的实际检查。
- `evidence/graybox-ready.png`、`graybox-racing.png`、`graybox-finished.png`：实际浏览器截图。

详见 [验证报告](VALIDATION.md)。测试结果不代表 APK/WebView 真机、最终模型/骨骼、20 分钟持续运行、真实跨区网络或商业并发压测已经通过。
