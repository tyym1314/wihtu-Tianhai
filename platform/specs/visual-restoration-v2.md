# 设计图还原 V2 · 差距、制作路线与验收标准

日期：2026-09-19。状态：**第一轮可玩视觉重制已落地；尚未达到全量设计还原验收**。

本轮逐张复看了十款原始三屏设计，并对照现有对局截图、实际结算截图、素材目录和动画代码。用户关于精致度、布局和动效差距的反馈成立。前一阶段的功能、接口和账务验证不能代表视觉还原验收。

在线对照台：`http://127.0.0.1:8795/design-review/index.html`。展示原始完整设计板与已保存的实际游戏截图，逐款列出缺口。不同截图的局势、人数和外部工具栏不一致，因此当前不报告没有依据的“还原率百分比”。

## 1. 已确认的差距

| 游戏 | 当前与原图最重要的差距 | 重制主线 |
|---|---|---|
| 三消 | 狐狸只有头像与整体摇动，缺身体、手臂、服装和举杯；宝石反射/轮廓简化；底部控件与结算不同 | 统一狐狸角色、宝石图集、原稿布局、逐波连消、狐狸举杯结算 |
| 高尔夫 | 已有真 3D，但石桥、岸壁、植被与水面的几何/纹理过于简化；镜头偏高，金球偏小 | 场景模块、材质、柔和光照、相机、果岭特写和金球奖杯 |
| 保龄球 | 球馆、漆面和灯带倒影不够精细；球瓶占比和低机位没对齐；缺完整全中/奖杯演出 | 球馆模型、球道材质、反射、出手/跟球/撞击摄影与主题结算 |
| 动物竞速 | 动物是程序几何组合，缺蒙皮骨骼、服装和表情；赛道纵深、冲线正面摄影、领奖台缺失 | 四个正式动物角色、动作包、赛道模块、冲线与领奖台 |
| Carrom | 棋盘/棋子是渐变绘制，缺木纹、厚度、雕边和阴影；顶部较散、底部控制不同 | 正交木盘/棋子材质、紧凑 HUD、瞄准控制、进袋与雕花奖杯 |
| 飞镖 | 简单城市剪影替代蓝紫赛场；字符飞镖替代金属物体；飞行终点未映射实际命中点 | 场馆绘景、靶面与金属飞镖、真实落点动画、牛眼及专属胜利 |
| Ludo | 头像/骰盘偏小，棋盘缺玉石质感；骰子是正面图翻转，吃子直接回基地 | 玉石盘、立体棋子、六面骰、吃子弧线、红棋角色举杯 |
| Jackaroo | 四边围桌座位变为顶部条，厚胡桃木四叶盘变方板；选牌会缩棋盘 | 固定盘面、四边座位、木盘/弹珠/手牌托架、同时换位与队伍胜利 |
| 多米诺 | 大头像和横牌托架缺失，环境为剪影；牌统一从固定偏移出现，抽牌重播整手 | 宫殿层次、象牙牌与托架、来源正确的落牌/抽牌、专属奖杯 |
| 八球 | 木框、台呢、袋口深度、球面高光与底部控件简化；缺黑八尾迹和专属胜利 | 分层球台、球材质/自转、球杆动作、入袋遮罩、黑八奖杯 |
| 虎虎生财 | 当前有原创红金背景、角色姿态和符号素材；未找到独立确认过的三屏设计稿 | 先锁定现有原创主题或此前 PG 构图参考，继续使用原创素材 |
| 雷霆王座 | 用户认可度较高 | 保留为现有基准，做必要兼容回归 |

**共通问题是原稿第三屏。** 当前十款竞技进入终局后由 `arena/main.jsx` 的通用奖杯/榜单接管。每款设计的专属角色、奖杯、背景、领奖台和队伍奖额层级基本没有实现。

另发现并已单独修复 Carrom 与 Pool 的奖池展示单位：最小单位应除以 100 后展示为金币；没有修改任何入场金额、服务费、派奖、规则或钱包。

## 2. Blender 的明确用途

**应引入 Blender 作为正式美术生产工具。** 它承担模型、UV、材质、光照烘焙、骨骼、动作和相机预演；网页继续使用现有可用渲染框架。

| 场景 | 建议实现 |
|---|---|
| 高尔夫、保龄球、竞速 | Blender 制作模型、材质和动画，导出 glTF/GLB，接入当前 Three.js；模型的可视细节与权威碰撞形状分开管理 |
| Carrom、八球、Ludo、Jackaroo、多米诺 | Blender 制作统一光照下的棋盘/球台/牌/骰子/奖杯，固定视角资产预渲染或烘焙；运行时用真实棋子、牌、球和事件时间轴合成 |
| 三消、虎虎生财 | 精细分层角色或骨骼/姿态动画；宝石、符号、金属边框与奖杯可用 Blender 制作透明图集，保留 2D/2.5D 交互 |
| 飞镖 | 固定镜头场馆使用分层绘景；飞镖与必要的靶面细节用轻量 3D，命中轨迹绑定实际事件 |
| 字体、按钮、HUD、排行榜 | 使用精确尺寸的可编辑布局、组件状态与矢量/九宫格资产。Blender 不负责代替文字排版与点击逻辑 |

Blender 支持导出对象/骨骼等动画，材质节点需满足目标格式约束；复杂光照、法线和环境遮蔽可烘焙为贴图。Three.js 已提供 glTF 加载、贴图压缩适配与动画播放能力，现有引擎可以承接这些资产。[Blender glTF](https://docs.blender.org/manual/es/4.5/addons/import_export/scene_gltf2.html)、[Blender 烘焙](https://docs.blender.org/manual/id/5.0/render/cycles/baking.html)、[Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、[AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)。

其他工具按用途选择：

- **Figma / 可编辑 SVG 布局稿**：固定画布、图层、边距、字号、按钮状态与安全区。现有 PNG 只有扁平图，需补成可执行规格。
- **Spine**：适合狐狸、老虎这类 2D 骨骼角色；正式使用需具备对应许可。当前不能写成已经有 Spine 工程或已完成集成。也可使用 Blender 动画导出的透明图集，但要控制体积、帧率和姿态衔接。[官方运行库与授权说明](https://esotericsoftware.com/spine-runtimes)
- **图像生成与绘图工具**：补环境、纹理和分层原画；统一角色与光照后再制作可运行资产。重新生成一张更漂亮的整屏图不构成游戏还原。
- **Canvas / Three.js / 现有动画层**：接收实际动作，驱动交换、碰撞、运动、镜头、粒子和字效。无需仅为名义上的“更高级”更换全项目引擎。

Blender 的存在本身不保证好看。每项资产必须在浏览器的真实相机、灯光和屏幕尺寸下看效果，离线渲染图与运行截图分别验收。

## 3. 把“完全还原”落成明确标准

### UI 与材质

1. 以十张原始三屏 PNG 为美术母版，分别锁定 PLAY / MOMENT / VICTORY。保留构图、配色、主体比例、角色、按钮造型、装饰和光照方向。
2. 把原稿适配为 **390×844** 标准交付画布，派生 **360×800、430×932**；标出合作方工具栏与真实安全区。原图比例与设备不同，不能通过拉伸整屏图假装还原。
3. 为头像、主体、棋盘、奖池、底部控件、结果主体建立锚点与尺寸表。固定 UI 的目标位置/尺寸误差控制在标准画布约 2 CSS px，前提是已完成尺寸稿；当前未达到或验证这个标准。
4. 模型轮廓、纹理、金属/木材/象牙/玉石材质、环境层次和接触阴影分别核对。缺少主角身体、整套环境或主题奖杯时直接判为未完成。
5. 文字、金额、骰子点数、合法棋盘、牌面和动作均绑定真实状态。分数与局势无需复制设计图中的示例数字；AI 示意图的错误格数不能替代引擎合法拓扑。

三消原图中的炸弹/洗牌数量按钮没有对应当前已确认玩法。需要明确功能规格后才能成为真实道具，不能只覆盖假按钮，也不能悄悄增加影响竞技公平的能力。聊天/表情/语音按钮同样需要有效宿主接口或明确状态。

### 动效与声音

原稿中间屏是静态关键瞬间，没有定义完整时间曲线。每款补一段可审查的分镜和实际带声演示，包含：待机 → 输入预备 → 权威受理 → 主动作 → 命中/连锁 → 得分反馈 → 收束 → 终局。

- **人物**：呼吸、眨眼、耳尾、手臂、躯干和表情有各自驱动；动作与胜负相关，不用整张角色图的位移代替全部表演。
- **物体**：棋子/球/飞镖的路径、终点、数量、骰面与实际结果一致。木材/球/象牙的碰撞、落下和进袋各有恰当声音。
- **高光瞬间**：连消、牛眼、全中、换位、吃子、进洞、冲线各有自己的演出层次。粒子位置来自真实事件，数量和亮度有递进与回落。
- **镜头**：需要特写的游戏设计明确轨道和返回时机，不能遮挡下一次输入或改变权威命中区域。
- **结算**：最终动作播完后进入主题胜利层。金额仍读取后台，账务待确认时显示真实等待状态；不能延迟或伪造账务确认来配合演出。

当前应优先修复的表现机制：Jackaroo 双子换位同时运动；Ludo 吃子从命中点回家；多米诺从原手牌/牌堆飞到目标；飞镖飞行终点对应 `hit.x/y`；公共壳不要在 `active→settling` 时卸载最后一手动画。

## 4. 制作顺序与交付物

先把 **三消（角色/2.5D）和高尔夫（场景/3D）** 做成完整质量样板，包括主界面、真实关键动作与专属胜利。样板对照原稿检查通过后，同一制作规范扩展到其他八款；竞速的四角色资产可以并行制作。虎虎生财先明确基准再加入相同验证。

每款必须留下：

1. 原始参考、标准画布尺寸稿、组件/状态清单。
2. 可编辑源文件与运行资产：`.blend` / 角色工程、GLB 或透明图集、纹理、字体/音频来源与 manifest。
3. 真实事件与表现时间轴映射；取消、重连、重复事件和终局中断策略。
4. 同状态的原稿/实现并排图与半透明叠加图；完整带声操作录像。
5. 360/390/430 布局、宿主工具栏、音量/语音共存与资源加载检查。
6. 真机帧时间、内存和加载记录。没有设备数据时保留待验收，不把桌面浏览器模拟写成手机性能达标。

每款独立通过美术验收后再标记“已还原”。功能、账务、视效和性能是四个独立检查项，已有 322 项后端测试结果只能证明其覆盖的功能行为。
