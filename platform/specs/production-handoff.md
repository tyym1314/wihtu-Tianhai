# Tianhai 游戏平台 · 合作方接入与发布交接

当前公开入口为 https://game.tianyahuyu.com 。`/demo/` 使用测试币，管理平台提供合作方账号、App、签名密钥、钱包绑定和接入自检。平台不设置 100 人业务上限，按实际在线规模规划扩容；100 人是一次测试样本，容量结论以“版本与发布”页的实际报告及其测试范围为准。当前没有首发合作方，独立正式实例与上线验收仍待完成。正式 App 默认使用平台自有持久钱包，不要求另外接入第三方钱包；玩家开户余额为零，当前未提供充值功能。Android 真机结果按运行页的对应发布版本报告展示，iPhone 另行验收。

Android 原生入口、全屏容器与系统返回流程见 [Android 接入说明](android-webview-integration.md)。App 应展示自己的原生游戏图标，点击后加载单款游戏；网页版试玩大厅不是原生 App 的必选入口。

## 合作方从哪里开始

1. 平台管理员在“合作方与应用”创建合作方账号，通过双方约定的安全渠道交付初始密码。合作方首次登录后，在“账户安全”改密。
2. 合作方登录自己的工作台，创建沙箱 App，保存 App scope 和一次性 API secret。一个 App 仅属于一个合作方；不同 App 的用户、会话、钱包 scope、订单和密钥隔离。
3. 下载开发者中心的标准接入包，先阅读 `phase-f-self-integration.md`，运行包中的验证命令。参考钱包、固定测试用户和浏览器宿主只供沙箱联调；沙箱后端自行验证用户后才可签名调用 `/v1/sessions`。正式环境不接受合作方 HMAC 直接创建或恢复玩家会话，必须走平台自有玩家身份与同源 BFF，见 [正式玩家 BFF 说明](player-bff.md)。
4. 配置精确宿主 Origin；使用托管入口时配置正式平台自身 HTTPS Origin。默认平台钱包已与正式 App 持久绑定，无需外部钱包服务。仅显式选择 `wallet_provider:"external"` 的 App 需要由运维允许合作方钱包 HTTPS Origin，并在新建、暂停、没有会话和账务记录时完成一次性绑定。绑定不会迁移参考钱包余额，已有订单也不能改绑钱包。
5. 平台自有钱包使用持久原子协议，账号零余额可进入免费局，不会自动注资，充值与资金入口仍需独立交付。若选择外部钱包，合作方按 `wallet-protocol.md` 实现余额查询、冻结、捕获、派奖、释放、原订单查单，以及获准开放概率游戏后的完整周期负债授权；外部主钱包与 App 送礼、转账等业务应共用原子余额约束，并预建对应玩家账户。
6. 在沙箱接入页运行实际自检：签名目录、测试账号余额、启动码单次兑换、越权拒绝、未成局取消、双人扣款和判胜、重复扣款／派奖十次、按原业务号查单。自检会操作指定测试账号的测试币，不能指向真实用户钱包。
7. 提交真实 App 的 Android/iPhone WebView 验收记录、弱网与进程重启记录、持久账号和账务核对记录，并完成托管登录、未完成对局找回与所需的合作方跳转/回跳验收，再安排生产凭证与正式开放。外部钱包模式另须验证真实玩家账户预建。平台不把沙箱自检通过自动等同于生产通过。

## 请求保护与扩容

已认证玩家按 App 和用户分别计数，轮询与操作独立；不同 App 的合作方接口独立计数。登录和匿名入口保留基础 IP 防滥用。返回 429 时按 `Retry-After` 等待，并使用原业务请求号重试，不能另起一笔扣款。具体参数和部署方式见 `rate-limits.md`。

当前仍是单 API 实例部署。增加服务器前需接入负载均衡、共享限流层，并按实例数分配 PostgreSQL 连接及物理线程预算；增加服务器不是修改一个“最大玩家数”开关，也不能代替扩容后实际负载验收。

## 密钥轮换

接入页支持同时保留两把 `partner-to-platform` 密钥：创建备用密钥 → 安全保存 → 合作方后端切换 → 验证签名请求 → 明确撤销旧密钥。钱包方向密钥独立，不会被这个操作修改。

- `GET /api/partner/apps/{app_id}/integration/keys`：仅返回 key ID、有效状态、创建及撤销时间，不返回 secret。
- `POST .../integration/keys`：JSON `{ "request_id": "key_rotation_20260920_001" }`。请求号只接受 8–96 位英文字母、数字、下划线或横线。同一操作者、同一请求号在 10 分钟内可以重取同一次加密响应；期限后返回 `KEY_RESPONSE_EXPIRED`，不会创建另一把密钥。
- `POST .../integration/keys/{key_id}/revoke`：撤销属于这个 App 的合作方密钥。至少保留一把有效密钥。撤销不会取消已经受理的游戏和结算义务；已在途、已完成鉴权的请求可能完成，必须保留原业务号查单。

丢失创建 App 时的一次性 secret，使用上述轮换流程；不要将 secret 放入 H5、截图、日志或前端配置。凭证修改和撤销都有审计记录。合作方账号禁用会撤销控制台登录，不会自动暂停其 App 或取消已受理结算；如需停止新游戏，另外暂停对应 App。

## 沙箱与生产分离

每套运行实例只允许一种环境。`gp_runtime_identity` 将数据库与 `sandbox` 或 `production` 绑定；修改环境变量不能把原沙箱库变成生产库。生产实例需要独立数据库、master key、私有目录、API 端口和 HTTPS 入口。禁止复用测试币、参考钱包账户或沙箱 HMAC key。

生产运行必须设置 `OASIS_ENVIRONMENT=production`、`OASIS_START_WALLET=0`，显式给出 HTTPS Origin、数据库和私有目录，并预先安全生成 master key。生产不会种入演示 App、演示用户、参考钱包余额或演示钱包密钥。新建 App 默认暂停并使用[平台自有持久钱包](platform-wallet.md)：注册时原子创建 App 内玩家 ID 与零余额账户，免费局不发币。创建时指定 `wallet_provider:"external"` 则保持未绑定，随后绑定允许列表内的外部 HTTPS 钱包。两种方式都需配置宿主 Origin。正式 `POST /v1/sessions` 对合作方 HMAC 请求返回 `PLAYER_BFF_REQUIRED`；控制台也不会签发任意真实用户的游戏会话。仅平台同源登录 BFF 可以从平台保存的玩家身份派生 App 内 ID 并申请启动码。未开放准入或 App 暂停时阻止新注册和新玩家绑定，但已有受理会话可由原玩家恢复。新会话先做所选提供方的只读余额探针，任何错误都阻断创建；外部钱包仍需合作方预建玩家，不自动开户或发币。

`OASIS_PRODUCTION_ADMISSION_ENABLED` 默认关闭。只有完成首发合作方验收、手机和容量验收后，运维才可在单独生产实例中开放准入。这是运维发布开关，**不是自动验收证明**。概率数学档位目前仍为沙箱候选，生产禁止启用雷霆／虎虎生财；开放之前需完成所有下注档位、免费链、取整、最大负债和最终数学版本验收。竞技费率保存后只作用于新局，既有局继续使用入场快照。

目前公网实例继续承担试玩与合作方联调；没有建立未经验收的生产合作方或向真实钱包发送请求。正式托管登录/注册页面已实现，稳定入口为正式 HTTPS Origin 下的 `/player?app_id=<应用编号>`，需将该 Origin 配入 App 宿主允许列表。页面只调用玩家 BFF，使用真实账号和应用游戏权限；刷新、关闭页面或换设备后可从服务端读取自己的未完成竞技对局，准入关闭时仍能恢复原会话和房间，游戏返回玩家自己的大厅。沙箱实例会显示入口不可用。合作方外部跳转/回跳协议、账号验证/密码找回尚未完成，仍需与首发合作方验收。托管入口候选实现不等于已上线能力，详见 [玩家 BFF](player-bff.md)。

## 发布、监控与恢复

- 发布物采用独立版本目录、文件 SHA-256 清单和原子符号链接切换；私有配置、数据库及证书不进入发布包。
- `deploy/activate-release.py` 先校验清单、依赖和未完成对局，执行备份，停止准入后再次检查未决义务。新版本健康失败时切回上一份兼容代码，不回退数据库余额。仅对已验证兼容的增量迁移使用 `--compatible-schema`；该参数本身不证明兼容。
- 监控每分钟检查 API、数据库、钱包、试玩、HTTPS、结算积压、故障房间、备份新鲜度、磁盘和证书。报告有时间戳，超过三分钟视为过期。状态变化写入 systemd journal；目前未连接短信、邮件或 IM 外部通知。
- 每日备份含数据库转储及对应私有密钥。`deploy/restore-drill.mjs` 在随机隔离数据库中执行真实恢复，验证密钥解密、scope、余额和账本守恒，再删除演练数据库并记录清理结果。仅有备份文件或 `pg_restore --list` 不能算恢复成功。
- 2026-09-20 已将一份完整备份以 AES-256-GCM 加密后复制到管理员 Mac，并用仅保留在 Mac 的 RSA 私钥完成解密、归档及内部校验摘要验证。工具提供验证及还原到新私有目录的命令，见 `deploy/OFFSITE-BACKUP.md`。这是一份手动异地副本，尚未配置定时异地上传；正式运营前仍需落实自动备份目的地、保留策略和外部故障通知接收人。

完整运维命令和目录约定见部署交接文档。遇到钱包超时必须保留原订单号和请求内容，先查单，禁止新建订单“补发”、手工清空未决订单或重建密钥。
