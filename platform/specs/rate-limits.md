# 请求限流与扩容边界

限流限制的是短时间请求次数，用于约束异常重复调用和保护其他玩家；平台没有“最多 100 人在线”的业务开关。100 人只是一次业务规模假设和压测目标。实际容量取决于游戏组合、动作频率、服务器 CPU、数据库和钱包响应，不能由限流数字或短时间压力测试推算为已验收人数。

## 已认证请求

正常玩家不共享 IP 总额度。同一 Wi-Fi、公司网络或运营商出口下的玩家，按已鉴权的 `app_id + external_user_id` 分开计数。同一玩家重复打开页面、刷新 token 或切换游戏，仍共享同类请求预算，不能靠新会话绕过。合作方服务端请求在 HMAC、时间戳、nonce 和 scope 校验后按 App 计数；同一 App 的重叠轮换密钥共享额度，不同 App 即使共用出口 IP 也独立。

所有下列预算使用从该桶首次请求开始的 60 秒固定窗口，读取与写入使用不同桶；不是每秒平滑漏桶，也不限制同时在线人数。失败的已鉴权业务请求同样计数。

| 类别 | 默认每分钟次数 | 配额键 / 环境变量 |
| --- | ---: | --- |
| 竞技 GET，含 `/api/arena/session` | 900 | App + 玩家；`OASIS_RATE_PVP_READ_PER_MINUTE` |
| 竞技 `POST .../action` | 720 | App + 玩家；`OASIS_RATE_PVP_ACTION_PER_MINUTE` |
| 竞技创建、加入、准备、离开等其他写入 | 120 | App + 玩家；`OASIS_RATE_PVP_ROOM_WRITE_PER_MINUTE` |
| 概率游戏 GET | 360 | App + 玩家；`OASIS_RATE_PROBABILITY_READ_PER_MINUTE` |
| 概率游戏 spin、ack 等写入，合计 | 360 | App + 玩家；`OASIS_RATE_PROBABILITY_WRITE_PER_MINUTE` |
| 合作方 `/v1/*` GET | 1200 | App；`OASIS_RATE_PARTNER_READ_PER_MINUTE` |
| 合作方 `/v1/*` 写入 | 1200 | App；`OASIS_RATE_PARTNER_WRITE_PER_MINUTE` |

跑酷前端在上次 GET 返回后等待 150ms 再轮询，无响应延迟时约 400 次读/分钟；动作规则允许每 100ms 一次输入，即最多约 600 次/分钟。900 读与 720 动作分开计额，留出协议重试余量；规则级的输入冷却、BUSY、房间成员校验仍照常执行。720 不是允许绕过规则的动作数量。其他竞技游戏读取周期通常为上次 GET 返回后 500ms。

概率游戏前端在进入/异常恢复时读取 session，每球 spin 后播放动画并 ack，并非固定 500ms 轮询。360 次写入是 spin 与 ack 的总和，保留快速播放与重试余量。上述默认值是可调的基本防滥用策略，不是吞吐承诺。

## 未认证请求、登录与公开试玩

| 类别 | 默认规则 | 环境变量或位置 |
| --- | --- | --- |
| 玩家、合作方、兑换接口的失败鉴权 | 每 IP 120 次/分钟，超额返回 429 | `OASIS_RATE_AUTH_FAILURE_IP_PER_MINUTE` |
| 一次性 launch code 兑换 | 每 IP 1200 次/分钟，在消耗 code 前检查 | `OASIS_RATE_EXCHANGE_IP_PER_MINUTE` |
| 管理员/合作方登录 | Node 每 IP 12 次/分钟；部署 Nginx 6 次/分钟、突发 6 | `server/index.mjs`、`server/portal.mjs`、`deploy/oasis.nginx.conf` |
| 改密/账号凭据管理 | 每 IP 8 次/分钟 | `server/credentials.mjs` |
| 控制台 integration 写入 | 每 IP 30 次/分钟 | `server/index.mjs` |
| 试玩无签名 cookie / 无效 cookie API 请求 | 每 IP 1200 次/分钟 | `OASIS_RATE_DEMO_ANONYMOUS_IP_PER_MINUTE` |
| 已签名试玩访客的 API 请求 | 每 guest 240 次/分钟 | `OASIS_RATE_DEMO_GUEST_API_PER_MINUTE` |
| 试玩启动游戏 | 每 guest 40 次/分钟，同时计入上述 240 次 | `OASIS_RATE_DEMO_GUEST_LAUNCH_PER_MINUTE` |

试玩已取消“每 IP 每小时最多 20 个新访客”的人数式门槛。首次无 cookie 请求走宽松的匿名请求预算；签名 cookie 验证通过后走 guest 预算。同一 IP 其他访客不会占用该 guest 的额度。签名、CSRF、Host/Origin、独立测试钱包和重复启动不补充余额的规则保持不变。公开试玩仍只有测试币，正式合作方身份不经过试玩 guest 入口。

失败鉴权先验证身份再计入失败 IP 桶，使同一 NAT 下的有效玩家不因他人失败请求而被拒绝。该基本保护可以拒绝后续业务处理，但失败请求仍可能需要一次鉴权数据库读取；它不能替代边缘网关的连接、流量和恶意请求防护。匿名桶和已认证桶分开存放，避免无效 IP 耗尽已认证桶的存储。登录是未认证入口，仍可能受共享出口的登录突发影响。

真实 IP 只接受受信本地反向代理覆盖后的 `X-Real-IP`。不要把客户端自填的 `X-Forwarded-For` 或任意代理地址加入信任范围。

## 配置与 429 重试

表中的环境变量必须是 `1..1000000` 的十进制正整数；空字符串、0、负数、小数、Infinity 和含空白值均非法。API 和试玩进程分别在启动时校验自己的配置，非法配置会启动失败，不会静默关闭保护。未设置则使用表内默认值。变更配置后需要重启对应实例。

Node API 的 429 响应带 `Retry-After` 秒数，通常是该桶剩余窗口时间；无详细剩余窗口的既有登录/凭据保护使用 60 秒。试玩同样返回 `Retry-After`。当前 Nginx 登录限流由网关直接产生 429，网关响应格式独立于 Node API。

等待后重试时：

- 保留原业务 `request_id` / `requestId`、动作 `seq` 和业务内容。不要因 429 创建新扣款或新游戏操作。
- 合作方 HMAC 重试使用新的 nonce、当前 timestamp 和重新计算的签名；业务请求号不变。鉴权成功但业务被限流时，旧 nonce 可能已被消费。
- 一次性 launch code 的 IP 预算在兑换前检查，限流不会消费该 code；code 已过期时由宿主用原启动业务请求或既有会话恢复协议重新授权。
- 429 只表示限流，不作为成功、结算失败或扣款失败的证据；网络结果不明仍使用幂等查询/原请求确认。

## 当前部署能力与后续扩容

当前实现是**单实例内存限流**。进程重启会重置桶，多个 API/试玩实例不会自动共享额度，预算可能随副本数放大。内存桶有上限（API 的身份/IP 表分别 20,000，试玩 guest/IP 表分别 10,000）；达到保护上限时会暂时拒绝新桶并返回 429，过期后回收。这是内存保护，不是上线人数配置。

会话、启动授权、nonce、游戏房间/动作/幂等结果、在线时间、钱包操作和账本已持久化在 PostgreSQL，关键修改使用事务、行锁和 advisory lock。worker 队列、本进程锁队列、限流桶和部分恢复调度标记仍在内存。增加 API 服务器前需配置负载均衡及可信代理链、共享限流网关/存储、各实例 CPU worker 和数据库连接预算；不能把相同内存桶复制到多台机器后宣称配额全局生效。

目前每 API 的连接池配置上限合计 78（主池 20、参考钱包 8、session/cycle/PVP 锁池各 16、integration 2）；生产环境不启动参考钱包时该池通常不会建立连接。增加副本会增加数据库连接预算、恢复扫描和 CPU 竞争，需要按真实游戏组合再次验证。不要取消有界队列或扩大超时来掩盖过载。

容量报告应分别描述真实客户端的闭环轮询、固定槽位压力模型、动作分布、启动突发、测试时长与同机负载发生器开销。15 秒压力样本只能表明该次条件下的观测，不能作为精确的真实用户容量，更不能作为 100 人永久上限。
