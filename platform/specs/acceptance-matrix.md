# 平台与 12 款游戏验收矩阵

日期：2026-09-18。阶段 A 规格版本 `1.0.0`。本文件列的是必须执行的检查，除末尾“本阶段静态校验”以外，**所有运行、画面、声音、网络、钱包和真机项均未执行，不能据此宣称通过**。

依据：[规则册](game-rules-v1.md)、[资产生产计划](asset-production-plan.md)、[结构化目录](game-catalog.json)。最终交付要同时通过规则、金币、画面、动效、声音和实机，不以其中一项替代其他项。

## 1. 证据格式与签收规则

每份记录必须包含：检查 ID、日期、实际操作者、构建和资源 hash、规则/数学/物理/关卡版本、App 与环境、设备型号与系统/WebView、网络条件、动作/种子夹具 ID、结果、截图/带声录屏/日志路径、问题单和复测结果。随机种子和手牌证据按访问权限保存，不放到公开运营页。

- 状态只能使用 `NOT_RUN / PASS / FAIL / BLOCKED`；缺设备、缺真实资源或缺钱包能力均不是 PASS。
- 结算错误、跨 App 数据泄漏、可控胜负、规则不一致、有效中奖丢失、黑屏/无法操作为阻断项。主体美术、下半部按钮布局、角色动画或核心声音缺失也阻断该款游戏签收。
- 设计修正先给可对照的新稿并冻结为 production baseline，尤其是概念图中不合法的棋盘、牌数和物理布置。修正逻辑错误时保持已确认美术方向，不能默认为允许整体重做主题。
- 故障修正后复测对应条目与受影响路径；不重复跑与变更无关的全量长测来掩盖未定位问题。
