# Android 宿主接入与全屏游戏

接入方 App 在自己的原生页面里用 WebView（Android）或 WKWebView（iOS）打开游戏启动页（见接入指南第 4 节）。账号、余额和结算都在接入方自己的后端与钱包完成，平台不提供 APK。

## 宿主实现要点

1. APK 以 `/player?app_id=...` 打开真实玩家入口。游戏目录由服务端授权结果决定；13 个游戏路径白名单不会绕过服务器限制。
2. 游戏占满可用屏幕，保留系统手势与安全区。主玩法、计分区和主要操作应在一屏内可用，不能裁掉按钮或隐藏溢出。
3. 系统返回调用 `window.OasisPlayerHost.requestBack()`，由当前游戏处理退出确认、原请求及结算状态，再返回大厅。不得直接销毁活跃对局或把关闭页面当作退款。
4. 前后台切换遵守 WebView 生命周期，恢复时读取实际服务端状态。进程重启不能重新发币、重复扣款或把旧动作当新动作重放。
5. 保持 HTTPS 证书校验，禁用明文、混合内容、文件访问及任意外部导航。长期 API 密钥不进入 APK 或 H5；只有 QA 变体允许授权的 WebView 调试。

## 当前验收范围

实体 Android 和可用 VMOS 分别核对安装包、部署版本与设备信息。逐款检查全部 13 个游戏的真实目录、点击进入、一个合法操作的实际 HTTP 返回、结算、系统返回、按钮位置及显示流畅度；另检查断网重试、前后台恢复、进程重启和会话恢复。

每次报告保存对应设备、APK 摘要、部署版本与实际结果。构建通过或成功打开登录页不代表游戏验收通过。按本轮用户要求不执行并发压测，也不据此声明服务器容量通过；iPhone 留待后续实机验证。
