# 第三方游戏平台上线架构与质量裁决（2026-10-07）

**裁决：暂不开放第三方正式接入。** 现有模块化单体与服务端权威规则可以作为受控首发架构，当前障碍是体验、生产身份/钱包闭环、运行容量和验收证据，不是缺少微服务。正式开放必须逐项满足已冻结的 [移动质量标准](mobile-quality-v1.md)；本文件不降低任何门槛，也不把代码改动当成真机验收。

## 事实边界

- 当前公网试玩是独立访客测试身份和测试积分。管理端的真实 PostgreSQL 汇总、真实服务端规则与结算流程，不等于已经具有第三方正式用户身份和真实价值钱包。生产准入仍须绑定平台自有正式用户身份、持久化账本/结算、应用隔离和可审计对账；涉及实际价值时，还须完成对应合作方钱包契约与结算验收。
- 现有参考钱包确有持久余额、流水和幂等表，但 [参考钱包 README](../server/wallet/README.md)列明独立生产部署、密钥轮换、监控、备份恢复等缺口；其数据库还直接存储钱包签名密钥（`server/wallet/schema.sql`）。它不能通过换域名直接成为正式主钱包。生产配置与 systemd 文件目前只是模板，不能视为已上线。
- 合作方控制台登录不等于玩家登录。正式入口还需平台自有的玩家身份/BFF，用服务器验证的登录态产生稳定、按 App 隔离的玩家 ID，再签发一次性启动码；不得由网页自行传入任意正式用户 ID。当前 [production runtime](../server/runtime-mode.mjs) 对概率游戏另有限制，数学版本验收与明确准入前不能把两款概率游戏算作正式 13 款可开放。
- 已发布 `20261004-04` 的 [13 款质量记录](../review/deep-mobile-20261004/release-quality-status.md)为 **4 款 fail、9 款 insufficient**。13 款公网“一次操作—返回”检查通过，只证明那一次限定流程；真机完整局、内容体验、复杂局和全量容量未通过。
- 受控 390×844 / DPR 3 浏览器冷载的 `/play/run` 约 2.34 MB、最后资源约 3.90 秒；`/play/towerlink` 约 2.08 MB、最后资源约 3.37 秒。同会话第二次进入几乎全部命中缓存、约 0.20 秒。这个分解说明冷入口优先解决关键资源和解码；它不证明用户 iPhone 15 Pro 的网络或渲染数据相同，也不能把所有卡顿归咎于服务器。
- 2026-10-07 从本机直连公网、不经过本机 HTTP 代理，连续五次读取 `/demo/` 的 TTFB 为 253–333 ms，HTTP 均为 200。它只覆盖极小的 HTML 响应，不是游戏首帧、API P95 或手机网络证据；“服务器完全没问题”也不能由此得出。
- 同日只读核查线上仍为 `20261004-04`：4 vCPU、15.3 GB 内存中约 10.5 GB 可用，40 GB 系统盘已用 85%（剩余约 5.9 GB）；API、试玩宿主、Nginx、数据库和维护定时器当时均正常。源站本机的健康检查及 HTML/JS 首字节小于 1 ms，公网两次 HTML 首字节约 0.29–0.48 秒。这是一分钟闲时快照，不能推出高峰容量或 iPhone 持续掉帧的成因；系统盘余量已不足以让同机新增 mock 环境直接作为正式验收配置。
- 沙丘竞速旧局在渲染准备期间服务端已经推进；六条路线在无人输入的首 1.18–1.68 秒会遇到障碍。开局同步与恢复公平性是 P0，画面姿势插值只改善视觉连续性，不能被称为已经解决帧率或整场卡顿。本地 v2.1 候选已经实现所有真人画面就绪 ACK、统一倒计时、赛前超时/退出退款及更宽的首障学习窗口；隔离数据库回归通过，但尚未发布或在实体手机上验证。
- 新版沙丘竞速的测量须单列“本机首帧至就绪 ACK”、“等待其他真人就绪”和“统一倒计时”：只有本机已就绪后等待别人加载的时段可从客户端 LOAD-01 中排除；1.5 秒规则倒计时及 ACK 往返仍计入。准备期与倒计时不得计作持续运动的活动帧。
- 本机 100 会话/15 分钟只覆盖五款及特定硬件，保龄球内部处理 P95 98.697 ms，距离 100 ms 门槛很近。公网四核主机和剩余八款混合负载尚无通过证据。
- 本轮候选在本机定向测得：三消相同 65 秒/47 次交换的 React 提交 1,769→1,181，渲染累计 6,073→4,371 ms；多米诺相同 5 秒静止 20 牌桌的提交 64→12。这只证明重复界面工作减少；旧 Match 233.3 ms、Domino 116.6 ms、Tiger 149.9 ms 长帧未被复现或归因，原 `fail` 不撤销。详见[三消原始对照](../arena/match/qa/frame-20261007/README.md)、[多米诺短夹具](../arena/domino/PERFORMANCE-20261007.md)及[招财虎峰值边界](../../src/tiger/PERFORMANCE-20261007.md)。
- 沙丘竞速本地 v2.1 的 62 秒受控 Chrome 移动模拟仍出现一次 166.7 ms WebGL 帧和首次碰撞附近约 70–77 ms 主线程任务，未达到持续流畅门槛；把 HUD 从 100 ms 改为 250 ms 只减少 React 工作，还推迟首次可操作按钮约 80–118 ms，所以已撤回。原始记录在 [Run 持续运行夹具](../arena/run/qa/sustained-20261007/baseline.json)与[对照结论](../arena/run/qa/sustained-20261007/unlock-interval-audit.json)，不能据此称用户 iPhone Safari 的全程卡顿已解决。
- 后续 WebGL 计时把上述长帧定位为比赛中首次上传 1774×887 跑动图集和 1254×1254 动作图集到 GPU。当前候选在场景准备期间逐张预上传，受控 62 秒同负载从最大 166.7 ms 活动帧降为 16.8 ms，活动期间没有超过 50 ms 的帧间隔或 Long Task；六条路线各约 12 秒均未出现此类长帧。代价是本地冷入口可操作时间比单次基线约增加 330 ms，六条路线观察为 3.085–3.312 秒，未超过本项目 5 秒目标。详情见 [Run 图集上传诊断](../arena/run/qa/sustained-20261007/README.md)。这修复了本地可复现的图集上传卡顿，不代表 iPhone Safari 的整场体感已通过。
- 实体 Xiaomi 24053PY09C / Android 16 已经通过另一 ADB 服务的 5038 端口授权；默认 5037 端口只显示云手机。公开测试 APK 1.2.0 在该机上能打开原生大厅、`20261004-04` 的 Run WebView 和沙箱练习房；本次资源无 4xx、页面 JS 错误为 0。首轮 Run 驱动发生动作/序号竞争而未通过，重测跳跃 HTTP 200、个人序号 0→1；实体系统截屏显示赛道、角色与障碍，CDP 截图漏合成 GPU 图层，不能用那张空白图判断渲染失败。1.8 秒 RAF 采样也不能证明整场流畅。记录在本地 `platform/review/physical-android-20261007/`；这是已发布旧版的部分真机证据，不能替代本地候选验收。
- 公开旧版三消在这台 Android WebView 上首次出现 412×866 视口内文档多出约 5–6 px 的单屏失败；同机同版本重测却刚好 866 px，并完成交换 HTTP 200、序号 0→1。应保留间歇性布局缺陷线索。本地候选已收紧底部留白，隔离浏览器 412×866 界面回归通过，尚需实体机新候选多次复验。
- 公网旧版实体 Android 的 13 款单动作结果和版本边界见[逐游戏记录](physical-android-smoke-2026-10-07.md)：12 款首次严格脚本通过，三消首次失败后重测通过；它不是 13 款完整局或新候选的验收。
- 同机公开旧版 Run 的 60 秒前台 RAF 采样为 7,206 帧、P95/P99 间隔 8.4 ms、最大 16.7 ms，未见超过 33.4 ms 的间隔；这与用户 iPhone 15 Pro Safari 的“全程都卡”并不矛盾，设备、浏览器和版本均不同，还缺 iPhone Safari 的同口径完整证据。
- 在另一套全新隔离本地库与实体 Xiaomi Chrome 上，图集预上传候选版单次冷导航到首次可操作为 4.55 秒，触摸事件注入的首次跳跃 HTTP 200、个人序号 0→1；60,008 ms 前台采样约 3,600 帧，P95 16.7 ms、P99 16.8 ms、最大 33.4 ms，采样期 Long Task 0。退出重进可操作为 4.12 秒。三消真实 36 格棋盘的触摸事件交换也返回 HTTP 200、序号 0→1，412×794 活跃视口内文档同高。修复后本地候选版 13/13 均通过实体 Chrome 的单次注入操作或一次概率转动+ACK，TowerLink 拖线产生服务端行军单位；14 间测试房均取消，隔离数据库与 ADB 映射均清理。这是 Android **Chrome 注入触摸事件**的工程证据，尚非真人手指手感、公开域名、APK WebView、完整局、弱网或 iPhone Safari 验收；原始报告留在忽略上传的 `platform/review/physical-android-20261007/`。
- 20 Mbps 下行、5 Mbps 上行、50 ms RTT、CPU ×4 的 Run 冷入口夹具在图集修复后测得首次可操作约 5.826 秒；将未压缩的隔离测试单 bundle 压到接近发布分块体积后仍约 5.051 秒。两次都超过 LOAD-01 的 5 秒界线，且远不足规定的五次冷载 P95；不能用上述实体 Android 单次 4.55 秒覆盖这一未通过证据。资源时序显示场景 GLB 和 JS 传输/解析、场景就绪 ACK 与规则倒计时共同占时，下一轮应测真实发布分块并优先压缩/预取关键资源，不能挪走必要倒计时或让比赛先开跑来制造更快数字。

## 架构决定

| 层 | 首发决定 | 扩容或拆分触发器 |
| --- | --- | --- |
| 接入/身份 | Web 试玩、APK mock、第三方正式应用分别使用独立 origin、签名密钥、数据库与钱包范围；启动码一次性，所有动作按身份和 App 校验。APK 13 款完整玩法使用**独立在线 HTTPS mock 服务**和现有权威规则，不复用公网试玩访客或生产钱包。当前四核线上主机可在扩盘、限额和混合负载验证后承担短期内部试验；三方验收以独立主机及数据库为目标。 | 任何跨环境访问、失效的重放保护或钱包范围混淆，立即阻断发布。 |
| 规则/房间 | 保留模块化单体、版本固定的规则引擎、持久化局状态和已有异步物理 worker。不要仅为“像大平台”拆微服务；先处理开局同步、热点与长帧。 | 单机 CPU/事件循环/数据库连接在隔离压测中逼近门槛，或房间/结算工作相互影响时，按现有模块边界拆独立进程，再考虑水平扩展。 |
| 钱包/结算 | 生产正式用户与参考测试积分必须分离；扣款、退款、派奖要求持久幂等号、状态机、查单与日对账，故障不能依赖客户端重试来猜测成功。 | 未知交易不能收敛、账本不平或跨 App 可见，停止新局并修复，不靠扩容绕过。 |
| 资源 | 不含个人数据的指纹 JS/CSS/图片采用长缓存；HTML、启动接口、身份、余额、房间/结果 API 保持 `no-store`。首屏只阻塞首个合法操作所必需的资产，其余分批解码且帧内有预算。 | 静态资源占用 API 处理时间或网络冷载超标时，经 Nginx 配置验证后直出静态或接 CDN；保留旧指纹文件支撑回滚。 |
| 可观测性 | 逐游戏、版本、设备记录入口分段、帧间隔/长帧、输入本地反馈、请求确认、资产失败、内存/重进、房间和钱包终态。没有数据时状态是 `insufficient`。 | P95/P99、错误率或活跃房/待结算积压越过质量标准时可见告警与回滚，不以 `/health` 正常代替玩家体验。 |

APK 隔离的实际配置校验、独立库/密钥/端口和部署前置条件详见 [mock-sandbox 合同](../deploy/mock-sandbox/README.md)。目前这些是候选代码和模板；尚无已验收的独立 HTTPS 服务。

缓存依据是 [web.dev 的 HTTP 缓存指导](https://web.dev/articles/http-cache)：稳定指纹 URL 可长期缓存，未指纹页面需要明确再验证或不缓存。不要给动态或含身份内容使用共享长缓存，也不要在未验证缓存头与更新/回滚行为前引入 Service Worker 离线缓存。主线程任务可阻断交互，诊断要同时看真实帧和长任务，参见 [web.dev 长任务指南](https://web.dev/articles/optimize-long-tasks)。

当前候选的试玩宿主缓存实现及旧页跨版本取资源的保护见 [STATIC-CACHE.md](../deploy/STATIC-CACHE.md)。它的本地测试通过不等于已部署；`/arena/assets` 与 `/legacy/assets` 仍经过 Node，需要独立 Nginx 配置检查及容量复测后才能切换直出。

## 可执行的上线门禁

1. **候选构建**：规则版本和内容版本固定；后端、前端、APK 全量构建/契约测试通过；静态资源无密钥、旧局可恢复；新旧资源指纹与缓存头验证，失败保留。
2. **13 款逐游戏工程验收**：每款冷/热各五次、弱网五次、至少 60 秒活动帧、首手势/复杂局/十次进退/断网与后台恢复、完整结算返回。四个已知 fail 必须找到或消除可复现原因并由新候选重测；不因一次未复现覆盖历史记录。
3. **实体设备与人类验收**：用户 iPhone 15 Pro Safari、实体 Android WebView；每款至少 15 分钟或三完整局中较长者、30 次有效操作；至少五名非开发试玩者覆盖入门/中段/困难。2026-10-07 实体小米已在 ADB 5038 授权，公开旧版 Run 的重测单动作通过，但首轮驱动竞争和持续性能未验收；本地新候选及 iPhone Safari 的完整验收仍未完成。
4. **平台生产链路**：真实自有身份、持久化钱包/账本、应用/合作方权限、签名与幂等、退款/失败恢复、逐局对账、运维告警和密钥轮换演练。mock 与正式的跨环境请求必须 fail closed。
5. **容量与发布**：独立环境 13 款混合 100 会话/15 分钟，按每款分桶满足 P95/P99、错误、事件循环和 CPU 标准；公网预发布逐款启动—完整动作—结算/返回，记录版本/哈希、截图/日志、未结局和账本读回；逐步放量并保留可执行回滚。

当前已知的四个游戏 `fail`、九个 `insufficient`、正式身份/钱包与实体设备缺失，使以上门禁未闭合；因此不能给第三方使用“已上线可商用”的结论。每次新增证据更新 [13 款状态表](../review/deep-mobile-20261004/release-quality-status.md)或新的版本状态表，保留旧失败和版本归属。
