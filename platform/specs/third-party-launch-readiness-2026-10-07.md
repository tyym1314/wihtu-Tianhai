## 事实边界

- 当前公网试玩是独立访客测试身份和测试积分。管理端的真实 PostgreSQL 汇总、真实服务端规则与结算流程，不等于已经具有第三方正式用户身份和真实价值钱包。生产准入仍须绑定平台自有正式用户身份、持久化账本/结算、应用隔离和可审计对账；涉及实际价值时，还须完成对应合作方钱包契约与结算验收。
- 现有参考钱包确有持久余额、流水和幂等表，但 [参考钱包 README](../server/wallet/README.md)列明独立生产部署、密钥轮换、监控、备份恢复等缺口；其数据库还直接存储钱包签名密钥（`server/wallet/schema.sql`）。它不能通过换域名直接成为正式主钱包。生产配置与 systemd 文件目前只是模板，不能视为已上线。
- 合作方控制台登录不等于玩家登录。正式入口还需平台自有的玩家身份/BFF，用服务器验证的登录态产生稳定、按 App 隔离的玩家 ID，再签发一次性启动码；不得由网页自行传入任意正式用户 ID。当前 [production runtime](../server/runtime-mode.mjs) 对概率游戏另有限制，数学版本验收与明确准入前不能把两款概率游戏算作正式 13 款可开放。
- 已发布 `20261004-04` 的 [13 款质量记录](../review/deep-mobile-20261004/release-quality-status.md)为 **4 款 fail、9 款 insufficient**。13 款公网“一次操作—返回”检查通过，只证明那一次限定流程；真机完整局、内容体验、复杂局和全量容量未通过。

- 2026-10-07 从本机直连公网、不经过本机 HTTP 代理，连续五次读取 `/demo/` 的 TTFB 为 253–333 ms，HTTP 均为 200。它只覆盖极小的 HTML 响应，不是游戏首帧、API P95 或手机网络证据；“服务器完全没问题”也不能由此得出。

## 架构决定

| 层 | 首发决定 | 扩容或拆分触发器 |
| --- | --- | --- |
| 接入/身份 | Web 试玩、APK mock、第三方正式应用分别使用独立 origin、签名密钥、数据库与钱包范围；启动码一次性，所有动作按身份和 App 校验。APK 13 款完整玩法使用**独立在线 HTTPS mock 服务**和现有权威规则，不复用公网试玩访客或生产钱包。当前四核线上主机可在扩盘、限额和混合负载验证后承担短期内部试验；三方验收以独立主机及数据库为目标。 | 任何跨环境访问、失效的重放保护或钱包范围混淆，立即阻断发布。 |
| 规则/房间 | 保留模块化单体、版本固定的规则引擎、持久化局状态和已有异步物理 worker。不要仅为“像大平台”拆微服务；先处理开局同步、热点与长帧。 | 单机 CPU/事件循环/数据库连接在隔离压测中逼近门槛，或房间/结算工作相互影响时，按现有模块边界拆独立进程，再考虑水平扩展。 |
| 钱包/结算 | 生产正式用户与参考测试积分必须分离；扣款、退款、派奖要求持久幂等号、状态机、查单与日对账，故障不能依赖客户端重试来猜测成功。 | 未知交易不能收敛、账本不平或跨 App 可见，停止新局并修复，不靠扩容绕过。 |
| 资源 | 不含个人数据的指纹 JS/CSS/图片采用长缓存；HTML、启动接口、身份、余额、房间/结果 API 保持 `no-store`。首屏只阻塞首个合法操作所必需的资产，其余分批解码且帧内有预算。 | 静态资源占用 API 处理时间或网络冷载超标时，经 Nginx 配置验证后直出静态或接 CDN；保留旧指纹文件支撑回滚。 |
| 可观测性 | 逐游戏、版本、设备记录入口分段、帧间隔/长帧、输入本地反馈、请求确认、资产失败、内存/重进、房间和钱包终态。没有数据时状态是 `insufficient`。 | P95/P99、错误率或活跃房/待结算积压越过质量标准时可见告警与回滚，不以 `/health` 正常代替玩家体验。 |

APK 隔离的实际配置校验、独立库/密钥/端口和部署前置条件详见 [mock-sandbox 合同](../deploy/mock-sandbox/README.md)。独立 HTTPS 内部 QA 服务已运行，隔离与停止/重启验证通过；实体设备完整游戏验收尚未闭合。

缓存依据是 [web.dev 的 HTTP 缓存指导](https://web.dev/articles/http-cache)：稳定指纹 URL 可长期缓存，未指纹页面需要明确再验证或不缓存。不要给动态或含身份内容使用共享长缓存，也不要在未验证缓存头与更新/回滚行为前引入 Service Worker 离线缓存。主线程任务可阻断交互，诊断要同时看真实帧和长任务，参见 [web.dev 长任务指南](https://web.dev/articles/optimize-long-tasks)。

试玩宿主缓存实现见 [STATIC-CACHE.md](../deploy/STATIC-CACHE.md)，已部署的稳定静态仓库、锁文件与发布/回切覆盖门禁见 [STATIC-ASSETS.md](../deploy/STATIC-ASSETS.md)。02 的 `/arena/assets`、`/legacy/assets` 等受控资源路径由 Nginx 优先直出；HTML、身份及游戏 API 缓存边界保持独立。配置及静态公网验证通过不等于高峰容量或实体手机性能验收。

## 可执行的上线门禁

1. **候选构建**：规则版本和内容版本固定；后端、前端、APK 全量构建/契约测试通过；静态资源无密钥、旧局可恢复；新旧资源指纹与缓存头验证，失败保留。
2. **13 款逐游戏工程验收**：每款冷/热各五次、弱网五次、至少 60 秒活动帧、首手势/复杂局/十次进退/断网与后台恢复、完整结算返回。四个已知 fail 必须找到或消除可复现原因并由新候选重测；不因一次未复现覆盖历史记录。
3. **实体设备与人类验收**：用户 iPhone 15 Pro Safari、实体 Android WebView；每款至少 15 分钟或三完整局中较长者、30 次有效操作；至少五名非开发试玩者覆盖入门/中段/困难。2026-10-07 实体小米已在 ADB 5038 授权，公开旧版 Run 的重测单动作通过，但首轮驱动竞争和持续性能未验收；本地新候选及 iPhone Safari 的完整验收仍未完成。
4. **平台生产链路**：真实自有身份、持久化钱包/账本、应用/合作方权限、签名与幂等、退款/失败恢复、逐局对账、运维告警和密钥轮换演练。mock 与正式的跨环境请求必须 fail closed。
5. **容量与发布**：独立环境 13 款混合 100 会话/15 分钟，按每款分桶满足 P95/P99、错误、事件循环和 CPU 标准；公网预发布逐款启动—完整动作—结算/返回，记录版本/哈希、截图/日志、未结局和账本读回；逐步放量并保留可执行回滚。

当前已知的四个游戏 `fail`、九个 `insufficient`、正式身份/钱包与实体设备缺失，使以上门禁未闭合；因此不能给第三方使用“已上线可商用”的结论。每次新增证据更新 [13 款状态表](../review/deep-mobile-20261004/release-quality-status.md)或新的版本状态表，保留旧失败和版本归属。
