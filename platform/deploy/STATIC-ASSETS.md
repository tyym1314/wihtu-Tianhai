# 发布、缓存与回滚资源

`current` 切换只决定页面和应用代码。已公开的静态 URL 还可能被旧页面、浏览器缓存或回滚后的页面使用，不能随一次 Vite 清理或版本切换消失。

## 构建与完整包

`platform/retained-assets.lock.json` 固定公开资源包的 HTTPS URL、压缩字节数、SHA-256，以及每个资源的发布路径、内容摘要、类型、来源 release manifest 和依赖。构建流程先完成全部 Vite 构建，再恢复这些资源，最后记录构建清单。缓存位于被 Git 忽略的 `platform/.local/retained-assets/<sha256>.tar.gz`；首次构建使用严格 TLS、禁止重定向的下载，已有缓存也重新验摘要。损坏缓存不会被静默替换。

资源包只接受经过检查的 USTAR 普通文件和必要目录。拒绝绝对路径、路径穿越、符号/硬链接、特殊文件、PAX/GNU 扩展头、多余条目及摘要冲突。压缩包和总解压内容分别限制为 512 MiB。锁不是对运行时依赖的自动证明；增加条目时仍需审查真实 import、CSS URL、模型和动态素材枚举。

完整运行包必须包含全部锁定资源，及与旁文件一致的 `RELEASE-MANIFEST.json`。增量暂存必须保留旧版本已存在的指纹 URL 和前版锁条目，验证字节一致，并移除新 manifest 已删除的旧普通文件。不能依靠复制旧目录时偶然遗留的文件，让增量包通过而独立完整包缺资源。

初次锁来自 11 个保留版本：共审查 537 个实际文件，保留 528 个资源（476 个指纹入口、52 个依赖），原始大小 142,046,758 字节。固定 gzip 包为 122,779,415 字节，SHA-256 为 `113557f277c5206d0895db373c6e5b4b42641637bd4dbb52d5b04afb4797acbd`。出处是各项 `sources`，详细 AST/GLB/动态枚举审查记录在本地 `review/release/retained-assets-20261008/`。

已知历史边界保留在审查记录中：旧目录页面曾引用未曾提供的 TowerLink 截图和视频，本轮目录 UI 改为按实际媒体元数据显示；旧 Draco 的非 WebAssembly 回退文件未曾提供，不在支持的移动浏览器范围。SDK/接入文档下载链接属于可变接口文档，不属于这份不可变运行资源闭包。资产完整不能证明任意历史 JavaScript 与新版后端协议兼容。

## 公网静态库

`/opt/oasis/static-assets/` 按公共 URL 路径保存经核对的资源，与 `current` 独立。发布工具只追加候选 manifest 中受支持的指纹资源和锁定依赖，先核验全部源文件、已有资源及同 URL 冲突，再原子增加文件和登记收据。相同 URL、不同字节一律拒绝，不能覆盖旧资源来完成发布；素材变化需要新的 URL。工具使用既有 release 锁并保留至少 3 GiB 可用空间，不修改页面、数据库、Mock 或运行指针。

激活前须核对整个已登记集合和候选所需集合。因此切回旧代码也不会删除已发布的新 URL。完整包仍自带资源，独立静态库不是精简运行包或省略灾备材料的理由。只有文件复制、收据和激活门禁全部通过，才能声称候选已具备回滚时的资源覆盖。

Nginx 只对 `/assets/`、`/previews/`、`/arena/assets/`、`/legacy/assets/`、`/legacy/bundles/` 和 `/mark.svg` 使用静态库；库中没有的普通当前资源回退到原发布目录或游戏静态服务。缺失静态资源返回 404，不能返回 SPA HTML 和 200。点文件和敏感扩展的拒绝规则优先于静态规则。HTML、API、SDK、APK 下载和独立 Mock 域名继续使用原有路由。

八位构建指纹及显式十位移动图指纹使用一年 `immutable`；其他依赖使用 `max-age=0, must-revalidate`。静态库同 URL 的内容仍不能变化。页面不缓存，JSON/API 仍按原身份和响应规则处理。本次没有引入 Service Worker。

`/opt/oasis/release-artifacts/<sha256>.tar.gz` 仅用于公开、按内容命名的构建引导包。Nginx 仅开放完整 64 位小写 SHA 文件名，不列目录。不得将整个 release、配置、数据库备份或私钥放入该目录。

## 验证与恢复

发布顺序：完整构建 → 清单验证及打包 → 暂存独立候选 → 发布并核验静态库 → 激活前检查 → 切换及健康检查 → 公网浏览器与原会话清理读回。首次静态库上线还要检查 MIME、缓存、Range、ETag、缺失文件、敏感路径，以及页面切回旧版后读取新版资源的结果。

Nginx 配置要先在独立实例验证路由，再进行全量配置检查、备份和原子替换；失败时恢复备份并重新检查。真实回滚不得用修改旧 release 内容来实现。这里的静态恢复验证不能代替数据库兼容、钱包结算、真机性能、完整关卡或玩家体验验收。

本轮没有自动删除静态资源的逻辑。未来清理必须另行明确缓存存活期、活跃页面、可回滚版本和离线副本，不能只按文件 mtime、最近访问日志或当前 manifest 判断无人使用。
