- Review found and fixed an engine ordering edge: Golf's third shot timeout and another player's disconnect at the same tick now batch before choosing a winner, while an already completed third-hole score is preserved. The engine owner's two additional regressions are included in the 81-test runs.
- The former test setup used random App scopes inside the live database. The live API tick could read a fixture before `deadline()` changed its clock, then overwrite that change with its older snapshot; the fee test consequently saw `result:null`. Scope names alone did not isolate background workers.
- The corrected setup creates a unique temporary database before dynamically importing any backend pool, sets both database URL and temporary local-key directory, and verifies `current_database()`. Recovery children inherit the explicit test URL and refuse non-test databases. Deadline fixture mutation also takes the room advisory lock. No service implementation was changed for this fix.
- Both generated databases were dropped in `after` after HTTP servers and pools closed. Creation/drop names appear in each TAP; an independent maintenance query confirmed **no matching temporary PvP databases remain**. The live API returned healthy before, between and after both full test runs.
