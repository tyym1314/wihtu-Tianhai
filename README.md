# THUNDER THRONE · 雷霆王座

手机竖屏 6×5 连消 Slot 可玩演示版。使用已确认设计稿的角色、场景和符号素材，以独立 DOM 精灵、CSS 动画和 Canvas 粒子呈现。结果在 Node 服务端生成；浏览器播放相应盘面序列。

## 启动

需要 Node.js 22+。

```sh
npm install
npm run build
npm start
```

打开 http://127.0.0.1:8787 。开发模式使用 `npm run dev`，前端 http://127.0.0.1:5173，通过 Vite 代理 API。

默认只监听本机。若自行在可信局域网测试手机，可设置 `HOST=0.0.0.0 npm start` 后使用这台 Mac 的局域网 IP；本项目未公开部署到互联网。HTTP 局域网环境的浏览器功能可能与正式 HTTPS WebView 不同。

## 已实现

- 6 列 × 5 行，8+ 同符号任意位置计奖，分档赔付，连续消除与重力补位。
- 倍率球、15 次免费转、免费转重触发、免费倍率累积。
- 投入 10 / 50 / 100 / 200 / 500 演示币，免费期间锁定触发档位。
- AUTO 可选 10 / 25 / 50 / 100 次付费旋转；免费转自动衔接且不占次数。
- 中英阿三语言，阿语面板 RTL，数字及逻辑盘面保持正确方向。
- 32 秒原创循环配乐，旋转/停轮/小奖/大奖/免费转音效，独立音乐与音效开关、音量及中奖试听。
- 快速旋转、规则赔表、历史记录、重置试玩、免费转与大奖演出预览。
- 6 列循环滚轴、逐列停轮、中奖碎片与冲击波、雷电、持续金币雨和金额递增。
- 上部使用透明人物与独立场景：头部、躯干、披风、持杖手臂分别运动；待机呼吸、摆头、披风摆动，旋转/中奖/免费转时举杖响应，搭配法杖电弧与云雾。
- 底部接入参考原稿生成的神殿露台背景，上叠独立金边数值牌及 120px 主旋转按钮。
- 独立演示钱包，初始 12,000 币，服务端加密随机数，整数金额结算。
- 请求幂等、未确认结果恢复、原子文件存档、多页面版本校验。

演出预览不调用旋转 API，不改变余额或免费状态。它不参与 RTP 统计。

## 自动旋转

点击 AUTO，选择付费旋转次数后开始。每轮完整播放并确认结果之后才会请求下一轮；免费转不扣选定次数，最后一次付费旋转触发的免费转也会继续完成。

点击 AUTO 或大奖面板中的停止按钮，会取消后续旋转；已提交的当前轮继续完成演出和确认。切到后台、连接或确认异常、发现其他页面改变会话状态时停止；余额不足时不发起新的付费请求。自动队列只保存在内存中，刷新后不会自动启动，待恢复的单轮结果仍可按原流程继续。

v2 的 28 项自动测试与最终构建已通过。最终画面已截图核验：390×844 的 Auto 状态条不增加页面高度，320×568 阿语 Auto 面板可竖向滚动且未观察到横向溢出。浏览器操作、尺寸和结算读回见 [v2 验收记录](output/qa/visual-v2.md)；[首版验收记录](output/qa/acceptance.md)保留为历史基线。

## 人物与声音

v3 使用二维分层角色，不是实时三维模型。角色动作由独立关节变换驱动，不再仅靠整张图上下浮动；图片加载失败时保留原版背景。隐藏页面暂停动作，系统减少动态效果设置下保留静态角色。

浏览器需要首次点击后才能播放声音。点击人物区的音乐提示或开始操作即可解锁；右上角喇叭控制总静音，设置内单独调节配乐和音效。开关及音量保存在本机，刷新保留偏好；切到后台停止播放，返回后恢复已经解锁的配乐。音频初始化失败或被浏览器阻止时，不阻塞游戏旋转。

v3 新增 8 项音频测试，连同原有 28 项测试通过；手机浏览器验证和音频 PCM 检查见 [v3 验收记录](output/qa/visual-v3.md)。独立试听文件在 `output/audio/`，由游戏同一音频生成函数导出。

## 数值

目标 RTP 约 99%，固定概率与赔率，不按玩家输赢改变。独立 1,000 万付费周期（包含触发的全部免费转）模拟观察 RTP **99.2185%**，近似 95% 区间 **98.7970%–99.6400%**。这属于开发模拟结果，不是精确理论证明或第三方认证。

完整规则、模拟方法、源码指纹及不同投入档位的舍入核查见 [数值报告](output/math/README.md)。

```sh
npm test
npm run build
npm run simulate -- 10000000 19092026 10000 output/math/verification-10m.json
```

## 接口

- `GET /api/session`：演示会话、余额、免费状态、epoch、stateVersion、未确认结果。
- `POST /api/spin`：`{ requestId, bet, expectedVersion }`。新请求验证会话版本，重复请求返回原结果。
- `POST /api/round/ack`：`{ roundId }`，确认动画播放，不再次结算。
- `GET /api/history`：最近 20 局。
- `POST /api/reset`：`{ requestId }`，重置演示余额和奖励状态。
- `GET /api/config`：固定概率、赔率、规则和数值版本。

API 的 session / round 对外金额为展示币；`round.engine` 和引擎输入输出的金额为整数最小单位，100 最小单位 = 1 币。不要混用。

## 当前边界

此版本仅接隔离演示钱包，未接用户 App 登录、真实虚拟币、礼物系统或房间消息。存档在 `.data/demo-sessions.json`，设计为本地单进程演示；不能直接作为多实例生产钱包。正式接入需要把结算事务与认证迁移到现有服务，进行真实 WebView、弱网、并发和账务联调。

原始设计图在 `output/design/thunder-throne-v1/`。运行时使用 `public/assets/` 下的图像，以 CSS 精灵方式展示符号；`public/assets/throne-deck.png` 为无 UI 的神殿露台底图，实际控制牌和按钮独立叠加。`hero-scene.png` 是去人物背景，`hero-character.png` 是真实透明人物，由 CSS 裁片组成头部、身体、披风和手臂关节。角色与场景的立体感来自预渲染图像和二维分层动作，尚无实时 3D 模型或 Spine 网格骨骼资源；可在后续美术生产中替换，不改变开奖规则。
